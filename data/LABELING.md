# 数据标注规范（data/）

本目录的数据用于「记账及资产账户管理 vs 其它意图」的判别。**先定规则再写数据**——否则同一个句子在不同人手里会得到
不同标签，指标再好也没有意义。

## 1. 文件与规模

| 文件 | 用途 | 规模 |
| --- | --- | --- |
| `labeling/<标签>_data.txt` | 训练 + 调参（仓库默认数据，`-i data/labeling` 合并读取） | **1570 条**：`accounting_data.txt` 722 / `unknown_data.txt` 848 |
| `probe/<标签>_data.txt` | **独立留出测试集**（与训练集 0 重叠，不参与训练；`-t data/probe` 合并读取） | **499 条**：`accounting_data.txt` 206 / `unknown_data.txt` 293 |

训练数据**按标签一类一个文件**，每行仍是标准 fastText 格式（`__label__标签 文本`），合并后与原来的
单文件 `sample_intent_data.txt` 完全等价；所有文件都**没有注释行**（注释会被当成训练样本）。
新增/整理数据后可以重新拆分（幂等）：

```bash
python3 fasttext_training_script.py -i /path/to/full.txt --split-by-label data/labeling
# 或 make split-data SRC=/path/to/full.txt LABEL_DIR=data/labeling
```

留出集 `data/probe/` 用的是同一套命名与拆分命令（`--split-by-label data/probe`）：`-t data/probe`
会把目录里的两个文件合并后再评估，只想看某个类时直接 `-t data/probe/accounting_data.txt`。

## 2. 判定规则

一句话定义：**句子的主要意图是不是「记录/陈述已发生的收支，或查询/管理记账中的资产与负债账户」**。
是 → `accounting`，其它全部 → `unknown`。资产账户包括微信、支付宝、现金、银行卡、医保、公积金等；
负债账户包括信用卡、花呗、白条、贷款等。

按下面的顺序判定（命中即停），避免边界句摇摆：

| 顺序 | 若主要意图是…… | 判定 | 触发特征（示例） |
| --- | --- | --- | --- |
| 1 | 发起支付/转账/充值/还款**动作** | `unknown` | 帮我给电费账户充值500、帮我转200给李四、付一下这个订单、帮我充100元话费 |
| 2 | 提醒 / 待办 / 日程 | `unknown` | 提醒我明天交电费350、记得还信用卡2500、提醒我明天查询微信余额 |
| 3 | 注册登录账号、办理实体银行卡或授信、咨询操作方法 | `unknown` | 注册微信账号、申请招商银行信用卡、申请提高授信额度、记账软件里怎么创建资产账户 |
| 4 | **查询/管理资产与负债账户** | `accounting` | 查询我的微信余额、帮我新建支付宝账户、帮我创建招商银行信用卡账户、修改工行卡余额、花呗额度还剩多少 |
| 5 | 查询/统计收支、交易明细、账单及支付状态 | `unknown` | 这个月一共花了多少钱、哪一项支出最多、信用卡还款日是几号、我的退款处理到哪一步了 |
| 6 | 算数 / 换算 / 折扣 / 比价 | `unknown` | 128的20%是多少、1000块能换多少日元、800块打七五折是多少 |
| 7 | 记录**非收支、非资产账户**信息 | `unknown` | 记一下张三的电话、存一下WiFi密码、记下妈妈生日是3月5号、保存快递取件码 |
| 8 | 设置或咨询理财 / 预算 / 保险 | `unknown` | 这个月预算设3000、定期存款利率现在是多少、要不要买年金险 |
| 9 | 记账软件的其它元操作 / 元问题 | `unknown` | 打开记账软件、怎么把账本导出成Excel、记错了怎么修改金额 |
| 10 | 闲聊 / 知识 / 搜索 / 工具 | `unknown` | 给我讲个笑话、明天会下雨吗、设置一个早上七点的闹钟 |
| 11 | **陈述一笔已发生的收入或支出** | `accounting` | 午饭花了30块、工资到账8000元、已经转账给妈妈1000元、记一笔今天的停车费、外卖45 |

### 边界约定（每条都有真实样例在数据里）

* **「帮我」不是判据，动作才是**：`帮我给电费账户充值500`（支付动作）→ `unknown`；
  `帮我记一笔话费`（记录动作）→ `accounting`。同理 `已经转给妈妈1000元`（已发生）→ `accounting`，
  `帮我转200给李四`（请求）→ `unknown`。
* **充 / 转 / 付看「完成标记」**：没有 `了 / 已经 / 过 / 转过去了` 等完成标记的裸支付句统一按 `unknown`
  处理（`给朋友转账三千元`、`给电费账户充值500`、`给这个收款码付500块`）；带完成标记的已发生陈述是
  `accounting`（`给朋友转账了三千元`、`燃气充值150元`、`给爷爷转过去了1000`、`已经给房东转账1500块`）。
  同一动词只差一个「了 / 已经」就是不同标签，这是本数据最容易标错、也最需要成对收录的一类。
* **「帮我记一下」看后面接什么**：接**已发生的费用** → `accounting`（`帮我记一下交过的物业费`、
  `帮我补录昨天买药的45元`）；接**待办 / 时间 / 信息** → `unknown`（`帮我记一下明天要交物业费`、
  `帮我记一下物业费交到几月了`、`帮我记一下王经理的座机`）。
* **折扣 / 比价 / 算数一律 `unknown`**：`原价1200便宜到960打了几折`、`1200卖960是打几折`、`便宜了多少`。
* **按查询对象判断疑问句**：账户余额、可用额度、欠款余额、总资产/净资产/总负债、账户列表/数量查询
  → `accounting`（「微信零钱还剩多少」「查一下我有几张信用卡」）；收支统计、交易明细、账单日、支付状态查询
  → `unknown`（「这个月一共花了多少钱」「信用卡还款日是几号」）。
* **提醒句一律 `unknown`**，哪怕带金额：「提醒我明天交电费350」。
* **预算 / 计划 / 理财咨询**属于 `unknown`（「这个月预算设3000」「预算还剩多少」）；账户余额/额度查询
  和修改账本内的余额/额度 → `accounting`；向银行申请提高实际授信额度 → `unknown`。
* **新建账户指记账中的资产或负债记录** → `accounting`：微信、支付宝、现金、借记卡、信用卡账户均覆盖，
  可带初始余额或不带金额；注册登录账号、向银行申请开户/办卡 → `unknown`。
* **账户修改、对账和管理** → `accounting`：更新/陈述余额、设置期初余额、修改名称/备注/类型/默认账户、
  归档/隐藏/删除/恢复账本中的账户；密码、头像、银行预留手机号修改和实际注销银行卡/支付账号 → `unknown`。
* **直接执行与咨询方法分开**：「修改工行卡余额」→ `accounting`；「记账软件里怎么创建资产账户」
  「医保账户余额怎么查」「为什么银行卡余额和账本对不上」→ `unknown`。
* **无金额但明确在记录收支** → `accounting`：「记一笔今天的停车费」「把房租记上」「帮我补记一笔昨天的打车费35」。
* **极简口语** → `accounting`：「外卖45」「房租3500」「买菜56」。
* **中文数字金额** → `accounting`：「电影票四十五」「房租一千二」「燃气费交了八十」。
* **收入方向也算记账**：工资到账 / 红包 / 退款 / 报销 / 利息 / 分红 / 收到还款 / 卖闲置。
* **只问「记账是什么/怎么用」不算记账**：「记账是什么意思」「记账有什么技巧」。

## 3. 覆盖维度（构造时按格子铺满，不按条数堆）

只堆「XX 花了 N」会得到一个学不到边界的模型，所以每条轴都故意铺了不同说法：

| 维度 | `accounting` 侧 | `unknown` 侧（重点是**含金额的硬负例**） |
| --- | --- | --- |
| 金额写法 | 30 / 30元 / 30块 / 32.5 / 12块5 / 1,299 / 899.00 / 三百 / 一千二 / 九块五 | 128的20%是多少、1000块能换多少日元、一千二存一年利息多少 |
| 收支方向 | 花 / 买 / 交 / 付 / 充 / 订 / 到账 / 收到退款 / 报销回来 | 我上个月一共收入多少、帮我统计一下去年的总支出 |
| 行为主体 | 我 / 孩子 / 老婆 / 爸爸 / 妈妈 / 朋友 / 客户 / 公司 | 帮我给妈妈转1500、帮我给孩子的饭卡充200 |
| 动词强度 | 有明确动词（花了/交了/到账）与**无动词**（衣服八百八、团建人均200元） | 这个月打车花了多少、这个月花到三千了吗 |
| 时间词 | 昨天 / 上周 / 这个月 / 3月 / 补记 | 明天下午两点开产品会、提醒我月底交物业费600 |
| 口语 vs 书面 | 外卖45 / 通过支付宝支付了45.6元 | 帮我看看这月账本里哪笔最贵 |
| **同词不同意图** | 地铁充值100元、快递费花了15元、会员充值198元、停车花了10块、健身房月卡399元、买药花了45.8元 | 查一下公司附近的地铁站、帮我看看快递到哪了、帮我续费这个会员、这附近有停车场吗、健身房这个月去了几次、感冒了吃什么药好 |
| 硬负例（含金额不算账） | — | 这个月一共花了多少钱、提醒我明天交电费350、128的20%是多少、信用卡还款日是几号、这个月预算设3000、帮我给电费账户充值500、账单里那笔198元是什么消费、那笔156.8元是什么时候花的 |
| 信息记录 | — | 记一下张三的电话、存一下公司WiFi密码、记下妈妈生日是3月5号 |
| 账户查询 | 微信/支付宝/银行卡余额、信用卡/花呗额度、贷款余额、账户列表、总资产/净资产/总负债 | 收支统计、交易明细、账单日/还款日、支付状态、余额变化原因 |
| 账户创建 | 微信/支付宝/现金/借记卡/信用卡账户，银行全称/简称、带初始余额/额度或不带金额 | 注册微信/游戏/邮箱账号、办理实体卡、申请授信 |
| 余额与额度修改 | 修改工行卡余额、余额改成0/1288.66/一万二、设置期初余额、校准账面余额、更新账本里的信用卡额度 | 转账/充值/提现/还款执行、申请提高实际授信额度、提醒核对余额 |
| 账户管理 | 账户改名、改备注/类型/默认账户、归档/隐藏/删除/恢复账本账户 | 登录密码/头像/预留手机号修改、实体银行卡/支付账号注销 |
| 记账其它元操作 | — | 打开记账软件、怎么把账本导出成Excel、刚才那笔记错了怎么删 |

## 5. 已知残余错误家族（诚实记录）

本节为资产账户扩充前 v3 模型的历史错误记录；当前资产账户意图尚未重新训练或评估。

**「费用名 + 中文数字」且没有强动词的汇总式陈述**：`这个月停车费一共三百二`、`交了这个月宽带费九十`、
`衣服八百八`。这类句子与查询类（`这个月一共花了多少钱`）在字面上非常接近，模型概率常在 0.5~0.7 之间抖动。
处理方式：接业务侧规则（出现具体数字 vs 出现「多少/吗/几」）、提高 `--threshold`、或人工确认。

**「只差一个完成标记 / 一个宾语」的最小对**：这是 v3 修完 7 个线上 badcase 后剩下的主要风险。当时模型在
1441 条训练集上仍有 5 条自相矛盾（probe 417 / 新写 210 条均为 100%，说明不是泛化崩，而是边界太薄）：

| 真实 `accounting` | 真实 `unknown` |
| --- | --- |
| 给朋友转账了三千元 | 给朋友转账三千元 |
| 给房东转账了1500块 | 给房东转账1500块 |
| 付了停车费 | 付一下停车费 |
| 记一下这个月的房租 | 记一下王经理的座机 |
| 借给同事一千 | —（无同形负例，模型仍偏向 unknown） |

结论：小模型（dim 20 / 字符 1~3-gram）能学会「了 / 已经 / 过 / 转过去了」这类强标记，但**不要指望它稳定
区分只差一个字的句子**。业务侧如果对这几对特别敏感，优先加规则层（完成标记词典）或继续成对补数据，
不要只靠提高模型容量。

另外：v3 的 8:2 切分验证集为 288 条，单轮指标在 0.96~0.99 之间波动；当前数据需另行评估，
**评估优先用 `-t` 留出集**。

## 6. 继续扩充的清单

1. 先扩「说法」再扩「条数」：优先补上表里还没有的格子（方言口语、带单位「角/毛/分」、
   公司/家庭多主体、语音识别常见的错别字与无空格写法）。
2. 硬负例永远最值钱：线上日志里把 `0.5~0.7` 的边界样本抽出来人工标注（主动学习，单条信息量最大）。
3. 每加一批数据，先检查格式、重复、跨标签冲突及训练/留出集重叠；用户要求暂不训练时，停在数据检查。
   待用户安排训练后，再跑留出集（`-t data/probe`）；**不要**用留出集反复调参，否则它就不再是留出集了。
4. 换标签名 / 加第三类时，保持 `data/` 下文件同格式，并同步更新 `README.md` 里的标签表与本文档。
